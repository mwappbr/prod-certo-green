- (event) architecture run opened (Create intent, Fast path); input: prd-hn-modernizacao.md + addendum.md; purpose: demonstração; spine é o único entregável (usuário)
- (direction) Propósito: demonstração (caso didático do SDLC com IA). Spine é o único entregável; artefatos extras só se o usuário pedir no fechamento.
- (decision) AD-1 Paradigma: BFF (Backend-for-Frontend) com back-end em portas e adaptadores (hexagonal). Front-end só fala com /api. Previne regras acopladas a Fastify ou à API do HN, e o front chamando o HN direto.
- (decision) AD-1b Direção de dependência: domain não importa de app, ports, adapters, http nem de bibliotecas de I/O; ports só declara interfaces; só adapters importam HN, cache ou Fastify. Previne testes unitários impossíveis (RNF-06).
- (decision) AD-2 Fronteira do formato HN: formato bruto só é tipado e parseado em adapters/hn; normalização e status derivado (ok, deleted, dead) ficam em domain. Campos ausentes viram nulo ou lista vazia, nunca erro. Previne formato bruto vazando (RF-10).
- (decision) AD-3 Contrato compartilhado: shared/contract é a única fonte dos tipos de resposta e dos códigos de erro, importada por server e client. Previne tipos redeclarados e divergentes.
- (decision) AD-4 Cache com único dono: toda leitura do HN passa pela camada app, que consulta o cache antes do cliente HN. Chaves item:{id} e list:{categoria}; TTL por tipo, vindo de config; guarda modelo normalizado e sanitizado com cachedAt. Previne leituras com idades diferentes (RNF-02, R-06).
- (decision) AD-5 Saída única para o HN: um cliente em adapters/hn com timeout, retentativas limitadas com backoff, concorrência configurável, unificação de requisições idênticas em voo, busca de comentários por nível com limite de profundidade e de nós, e stale-on-error com marca stale. Previne N+1 e cascata de falhas (RNF-01, RNF-03, R-01 a R-04).
- (decision) AD-6 Sanitização na fronteira: HTML de comentários sanitizado uma vez, na normalização, com lista de tags permitidas. Cliente renderiza por um único componente. Previne XSS (RNF-10, R-05).
- (decision) AD-7 Erros: toda falha sai como {error:{code,message}} por um único mapeador em http; erros do HN viram códigos de domínio antes de chegar a http. Previne formatos de erro divergentes (seção 7 do PRD).
- (decision) AD-8 Acesso a dados no front: componentes não chamam fetch; acesso só por client/src/api com um hook por recurso, com estados de carregamento, erro e vazio. Previne estados divergentes e perda de rolagem (RF-08, RF-12).
- (decision) AD-9 Configuração: back-end lê env só em server/src/config, validada na inicialização; .env.example documenta; sem segredos no repositório. Previne constantes espalhadas (RNF-07).
- (decision) AD-10 Testes por camada: domain com testes unitários; adapters/hn com teste de integração contra stub de fixtures gravadas; axe em CI para acessibilidade. Previne regras presas a integração lenta (RNF-06, O-03, O-04).
- (decision) Monorepo simples (uma pasta shared, server, client) com um Docker Compose; sem banco de dados e sem pacote compartilhado publicado.
- (assumption) [ASSUNÇÃO] Fastify sobre Express: addendum deixa em aberto. Lean para Fastify por validação de schema e suporte a TypeScript. Reverter se o plano técnico escolher Express; AD-1 e AD-7 não mudam.
- (version) Node.js 24 LTS (Active LTS desde 28/10/2025). Node 26 vira LTS em 28/10/2026; reavaliar após essa data. Fonte: tabela do Node Release WG (cdn.jsdelivr.net/gh/nodejs/release@main/README.md).
- (version) React 19.2.x. Fontes indicam 19.2.7 a 19.2.8 (jul/2026). Patch exato a fixar com npm view react version antes de travar.
- (version) Vite 8.x. Blog oficial do Vite anuncia 8.1 em 23/06/2026. Fonte: vite.dev/blog.html.
- (version) Fastify 5.8.x. Release de segurança 5.8.5 em abr/2026 (Wikipedia e newreleases). Há relatos não confirmados de 5.11.x; conferir a última 5.x com npm view fastify version.
- (assumption) [ASSUNÇÃO] TypeScript 5.x, Vitest, axe-core, Docker Compose v2 e create-vite (react-ts) como starter do front: versões não verificadas na web; conferir antes de travar.
- (question) Tamanho máximo da lista de IDs do HN: fontes de terceiros dizem 500 (topstories); o repositório oficial não confirma. Pendência do PRD; não bloqueia o desenho porque o cliente pagina.
- (question) Limite de taxa do HN: repositório oficial diz que não há limite documentado; tratar como risco (R-04) com concorrência limitada.
- (decision) Deferred (fora da spine): hospedagem em produção e provedor de CI; biblioteca de cache de consultas no front; valores de TTL, concorrência, profundidade e nós (plano técnico); roteamento do front; observabilidade além de /api/health; estilo e sistema visual (UX).
